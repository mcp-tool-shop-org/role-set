**オープンな環境で開発されたプロトタイプ。** アドバイザリーおよび実験的なものであり、インターフェースとデータ構造は予告なく変更される可能性があります。ロールセットが記述した内容は、誰かが確認するまでトレーニングデータにはなりません。すべての項目は、R&Dによる主要なチェックと、トレーニングセットに近づく前に2回目の確認を受けます。

ロールセットは、ロールを定義する項目を計画し、ライターが記述すべき部分を記述し、各項目が通過したゲートを記録します。また、コードでBタイプのパズルを構築し、モデルがそれを見る前に検証します。これはジェネレーターであり、審査官ではありません。優れたロールホルダーとは、人々が記述するロールパックの中に存在するものです。

ライターと批評家は、明示的なポートを介してのみ`http://127.0.0.1`にアクセスできます。それ以外の場合は、1バイト送信する前に拒否されます。ロールセットは、マシンをレンタルしたり、ポッドにアクセスしたりすることはありません。実行時にポッドを使用する場合、offrigがレンタルし、ロールセットはループバックトンネルのみを確認します。

設計図は、[docs/role-set-design.md](docs/role-set-design.md)と[docs/generator-design.md](docs/generator-design.md)にあり、プログラムと整合するように維持されています。実行ノートは、[docs/runs/](docs/runs/)にあります。

## インストール

Python 3.13以降（3.15が主なターゲット。CIテストは3.13、3.14、および3.15を実行します）。1つの実行時依存関係：[aspire-si-gates](https://pypi.org/project/aspire-si-gates/) 1.7.6（バージョン固定）。ゲートはコピーではなく、インポートされます。

```text
pip install role-set
```

ロールセット自体を操作するには、クローンし、uvにロックされた環境をインストールさせます。

```text
uv sync --frozen
```

## ロールパック

ロールパックは、人々が1つのロールに対して記述したテキストです。ロールセットは、それをスライスして提供し、何も追加しません。そのハッシュは、すべての承認されたレシートに記載されています。

- **検証者**（`roles/verifier`）。`pack sync`は、特定のコミットにおけるローカルのaspire-siクローンからコピーします。内容は、レッスン、18の特性、種類のテーブル、修正、およびルールです。`pack verify`は、コピーをマニフェストと比較します。新しいクローンには、ソースリスト、除外リスト、および`defects.jsonl`（レビューで発見された欠陥クラスのカタログ）のみが含まれます。残りは同期によって補完されます。
- **擁護者**（`roles/advocate`）。このリポジトリに人が記述したパックで、モデルのテキストは含まれていません。ディレクターは、2026年10月14日にパックを承認しました（プルリクエスト#56のコミット`ffb9546`）。バッチ1はそこでビルドされています。それは、#56がマージされるまで`main`にはありません。バッチ1には、3つの特性があります。`failed-gate-first`、`exact-figures`、および`faithful-relay`。擁護者の項目がパイロット読み取りに合格するまで、それはトレーニングデータにはなりません。

## T10ジェネレーター

Bタイプのパズルは、以前は手書きで記述され、その後チェックされていました。現在では、コードがパズルを構築し、検証し、モデルはそれを言葉で表現するだけです。ジェネレーターは、`role_set.generate`パッケージです。T10（厳密なサイズに関するレッスン：「正確に」、「少なくとも」、「最大で」）は、0.2.0で変更された部分です。また、T12レシピ（特定の日に有効だったエディション）もビルドされます。T11はビルドされません。

**構築によって検証済み。** ビルダーは、隠された解をサンプリングし、答えが確定するまで、その解で真である手がかりを追加し、答えが不要とするすべての手がかりを削除します。ソルバーはモデルをチェックします。次に、ビルダーはR&Dの4つのT10読み取りを実行します。「正確に」を「少なくとも」として読み、「正確に」を「最大で」として読み、「少なくとも」を「正確に」として読み、「最大で」を「正確に」として読みます。パズルは、これらの読み取りのいずれかを特性の手がかりに適用すると、答えが変化する場合にのみ保持されます。他のカウントの手がかりで合格するパズルは、欠陥クラス`trait_not_tested`であり、拒否されます。

**セルマップ。** 各パック、質問、およびシードは、構造セルにマッピングされます。エンティティの数`n`（3〜5）、カウントワード`op`、`k`（1〜n-1）、および`ifs`、`if`の手がかりの数（0〜2）です。セットの質問は、3つのカウントワードすべてを使用します。主張の質問は、「少なくとも」と「最大で」は主張の結論を変更できないため、「正確に」のみを使用します。使用可能なセルは1回プローブされ、`t10_cells.json`にコミットされます。

**主張軸`if_shape`。** 主張セルは、その`if`の手がかりの形状も指定します。7つの形状があります。`none`は、`if`がない場合です。`pos`または`neg`は、1つの`if`がある場合で、その結果の極性によって決まります。そして、`chain`、`shared_consequent`、`shared_antecedent`、または`disjoint`は、2つある場合です。縮小されたパズルが形状を失うビルドは、同じシード内で再試行します。

**アロケーター。** 1つの質問と1つの値のカウントに対して、20個のシードのファイルは、何かがビルドされる前に、最小コストフローによって1回割り当てられます。各パックの20個のシードは、20個の異なるセルを使用します。`if`の手がかりがないセルは、ファイル内で最大2回使用されます（ゼロ・イフ・キャップ）。他の訪問は、チューニングシードでより多くの異なるスケルトンを生成したセルを優先します。これらの重みは、2値と3値のパックで別々に保持されます。

**多様性の下限。** すべての層（セットと主張、2値と3値）において、少なくとも75％が異なるカノニカルスケルトンであり、スケルトンが3回以上出現することなく、1つのパックのファイル内でスケルトンが2回以上出現することはありません。下限は、ロックされたシードで判断されます。ロックされたシード101〜120では、3値の主張は118/120個の異なるスケルトンに達し、最大の繰り返しは2回です。

**コミットされたレコード。** `t10_record.json`には、1,280個のビルド（シード1〜20、61〜80、81〜100、および101〜120、すべてのパック、両方の質問）が含まれており、それぞれにセル、`if_shape`、試行回数、およびカノニカルスケルトンが含まれています。ジェネレーターソース、セルテーブル、キャパシティテーブル、およびパックデータに関するsha256が含まれています。テストは、ロールセット自体のインポートの下で閉じられているファイルリストを保持します。通常のCIテストジョブは、数分でハッシュと下限をレコードからチェックします。すべてのパズルの完全な再構築は、`sweep`ジョブとして、`workflow_dispatch`でのみ実行され、レコードからの違いがある場合は失敗します。

**キャパシティゲートとヘッドルーム。** `scripts/t10_usable_cells.py --check`は、各層の供給量、需要量、およびヘッドルームを報告し、ファイルが配置できない場合は数値で失敗します。`if_shape`を使用すると、3値パックは合計で61個の使用可能な主張セルを持ち、以前は27個でした。どのパックもゼロ・`if`訪問を必要とせず、テストでは、12個の3値パック（実際の6個とクローン6個）を、ファイル内で繰り返しなく配置します。

## コマンド

`role-set --help`は、コマンドを一覧表示します。以下の各行は、今日存在するコマンドです。フラグは、各コマンドの`--help`にあります。

| コマンド | その機能 |
|---|---|
| `plan` | シードから一連のデータを生成する際に、すべてのスロットを修正します。モデルの呼び出しは行いません。同じシードを使用すると、同じプランが生成されます。 |
| `cost` | プランの実行前に、必要なポッド時間とコストを見積もります（`two-card`または`frontier`）。これはあくまで見積もりです。 |
| `pack sync` / `pack verify` | ローカルのaspire-siクローンから、特定のコミット時点の検証用パッケージをコピーし、そのコピーがマニフェストと一致するかどうかを確認します。 |
| `harvest` | 固定されたリポジトリからライセンスチェック済みの抜粋をローカルプールにコピーします。クローンディレクトリは記録されません。 |
| `write` | ランナー。`--mock`は、モデルやコストを使用せずに実行します。実際の実行には、ループバック`--endpoint`と`writers.json`からの`--model`が必要です。`--wave write`、`critique`、および`rewrite`は、バッチを分割し、必要に応じて異なるホスト上で、ライターとクリティックを交互に実行します。その間には`wave-drafts.jsonl`が配置されます。 |
| `readout` | 各レッスンと種類ごとに、実行結果（成功または失敗）を、`batch-report.json`を含むディレクトリから報告します。 |
| `critic-control` | llama-server上で、レビューされた項目に対するクリティックを評価します。クリティックのGGUFとサーバーのハッシュ、およびマシン情報が必要です。さらに、レンタルホストから取得した許可とハートビートファイルも必要です。`--trait-leg`と`--answer-leg`がこれらの処理を実行します。 |
| `ingest` / `store` | ファイアウォールを配置した状態で、ストアにトランザクションを記録します。`store status`はトランザクション数を報告します。`store void`は無効なトランザクションを追加します。 |
| `pilot-auto` | 2026年10月11日のパイロット版で利用可能な有料ランチャーです。そのスクリプトは、パイロット版のQwenとGemmaのピンを名前で指定しますが、これらは`writers.json`には含まれていないため、`write`はそれを拒否します。 |
| `puzzle-check` | データファイルとその`.models.jsonl`サイドカーに対して、タイプBのソルバーを実行し、繰り返される事実の骨格を拒否します。 |

```text
uv run role-set plan --lessons T02,T03 --seed 0 --out plan.json
uv run role-set write --plan plan.json --pack roles/verifier --out out --mock
uv run role-set readout --run out/mock
uv run role-set puzzle-check tests/fixtures/puzzle-check/sample.jsonl
```

ジェネレーターは、まだ`role-set`コマンドを持っていません。その3つのスクリプトは、コミットされたテーブルとレコードを作成します。

| スクリプト | その機能 |
|---|---|
| `scripts/t10_usable_cells.py` | すべてのセルをプローブし、`t10_cells.json`を書き込みます。`--check`は、コミットされたテーブルに対してキャパシティゲートを実行し、プローブは行いません。 |
| `scripts/t10_cell_capacity.py` | チューニングのシード1、21、および41の各セルについて、層ごとに異なる骨格の数をカウントし、その結果を`t10_capacity.json`に格納します。 |
| `scripts/t10_variety_record.py` | 記録されたすべてのパズルを`t10_record.json`に再構築します。`--check`は、コミットされたレコードを検証し、ロックされたシードの数値を表示します。 |

## ゲート

5つの種類：

- **A.** 指導用の文章。評価はありません。バリデーターが実行され、特性チェックは参考情報として扱われます。
- **B.** 有限の割り当てパズル。ソルバーがモデルをチェックします。クリティックの回答は参考情報として扱われます。
- **C.** 意図的に欠陥が仕込まれたチェッカー、または正しかったチェッカー。評価と証拠のチェックは拒否されます。欠陥チェックは記録されますが、拒否はされません。
- **D.** 2ターン。評価と証拠のチェックは拒否されます。特性チェックは参考情報として扱われます。
- **E.** 記述式のクイズ、または評価クイズ。記述式のEには評価チェックはありません。評価型のEは、評価と証拠をチェックします。

評価と証拠のチェックは拒否されます。特性、回答、および欠陥のチェックは記録されますが、それらの制御がパスするまでは拒否されません。特性の評価は、全体で85%の基準に対して40.3%でした。最悪の特性は、70%の基準に対して12.5%でした。回答の評価は、90%の基準に対して62.7%でした。2026年10月11日の欠陥制御は、9/24でした。

タイプBのソルバーは、その閉じたルール形式のセット内で、有限の割り当てパズルを扱います。最大6つのエンティティ、3つの属性、および20万件の割り当てです。ソルバーは、推論をモデルに対してチェックしません。自由テキストのデータに対する評価キー付きのタイプBの項目は、ソルバーの範囲外であり、`puzzle-check`はそれを範囲外としてカウントし、合格とはカウントしません。

ストアのファイアウォールは、取り込み時に保留中のデータ、封印されたデータ、およびインタビューデータを拒否し、ステージ中にDEVデータを拒否します。これらのデータへの読み取りパスはありません。ステアリングは設計されていますが、まだ実行されていません。

## 実行が保持するもの

すべての承認されたトランザクションには、プランのハッシュとパッケージのハッシュが含まれます。実行でサンプルが使用された場合、サンプルコミットと除外ファイルのハッシュも含まれます。固定ルールが使用された場合、そのルールのハッシュが含まれます。生成されたパズルのトランザクションには、そのシード、試行回数、読み取り、難易度メトリック、および骨格、パッケージ、ソルバーのハッシュが含まれます。すべてのライターの呼び出しは、承認または拒否に関係なく、`drafts.jsonl`に保持されます。

## モデル

`writers.json`は、執筆者の一覧です。 メーカーのライセンスまたは契約条件に、その利用を制限する条項が含まれていない限り、利用は許可されます。黙認は制限とはみなされません。 各エントリには、検索されたキーワード、ページのURL、閲覧日、閲覧者、rndのライセンス登録におけるそのキーワードの識別子（`registry_id`、`licences/registry.json`）、およびトレーニングの評価結果（`allowed`、`conditions`、または`barred`）が記録されます。 そのレコードを持たないエントリ、または結果が`barred`であるエントリは、リストが読み込まれる際に拒否されます。 リストにない名前は拒否され、また、`cloud`を含む名前も拒否されます。

このモデルは、Nemotron 3 Ultra 550B、DeepSeek-R1-0528、Nemotron 3.5 Super 120B（これら3つは1つのポッドに配置）、そしてパイロットの8つのアーム：Nemotron 3.5 Bolt 74B（NVIDIA独自の24GB量子化対応ビルド）、Muse-Glimmer-30B、Nemotron 3.5 Lightning 30B、Qwen3.8-27B、Qwen3.6-35B-A3B、Granite-4.2-30B、Gemma-4-31B-it、およびDeepSeek-R1-Distill-Qwen-32Bで構成されています。評価を行うのは、Muse-Glimmer-30BとNemotron 3.5 Lightningです。ただし、作成者自身の系列のモデルは評価対象外とします。各モデルには、そのGGUFの作成方法と、パイロットの32,768トークンというコンテキスト長において、40GBのA100に適合するかどうかの情報が、`pin_note`として付記されています。

モデルは、CUDA 13.4を使用してビルドされたllama.cppの`llama-server`によって提供され、Q8_0で実行されます。リストに登録されているモデルは、ピンが付けられるまで拒否されます。ピンには、リポジトリの改訂、GGUFファイル、およびファイルのsha256が含まれます。ウェーブスクリプトは、起動前にGGUFと`llama-server`バイナリをハッシュし、実行時にリストからの逸脱は拒否されます。すべてのトランザクションには、パーティション（`production`または`trial:<name>`）、両方のモデルのファミリー、改訂、およびGGUFハッシュ、サーバーのコミットとハッシュ、およびCUDAマシン情報が記録されます。

**カードのパラメータ。** ライターとクリティックは、それぞれメーカーが文書化した設定で実行され、rndの`experiments/local-builders/card-values.json`から読み取った設定と`--cards`（ファイルJ2を読み込むため、両方のモデルで同じ設定が適用される）が使用されます。すべてのサンプリングキーとチャットテンプレートの設定は、無効になっている値を含むすべてのリクエストで使用されるため、`llama-server`のデフォルト設定はモデルに適用されません。サーバーは32,768トークンのコンテキストで実行され、応答には16,384トークンまで使用できます。これは、思考モードを持つすべてのモデルが思考を行うためです。R1-Distillのシステムテキストは、そのカードの指示に従って、ユーザーのターンに組み込まれます。ライターは、`writers.json`内のその`card` ID、またはそのサービス名によって、対応するカードと紐付けられます。レシートには、ファイルのsha256、候補、および実際に送信されたものが、ライターとクリティックに対して記録されます。実際の`write`または`critic-control`で、かつ`--cards`がない場合は拒否されます。

ステップは、そのマシンラインがColab VMまたはポッドを指定しない限り、許可の範囲内でのみ実行されます：`--grant`と、60秒以内に変更されたハートビートファイル。リグを指定する行は、カードに何が書かれていても、それらを必要とします。ハートビートファイルは開かれません。`--mock`は何もロードしません。

## パイロットテスト

3つの有料パイロットテストは、[docs/runs/](docs/runs/)に記録されており、すべて2026年10月11日に行われました：3.52ドル、3.61ドル、2.80ドル。これらは、このREADMEに記載されている唯一のコストの数値です。これらのいずれかの行も、トレーニングセットには含まれていません。パイロットテスト2では、R&Dのキーチェックで49件の候補のうち、15件がそのまま合格し、さらに15件が機械的な修正後に合格し、19件が不合格となりました。パイロットテスト3では、何も書きませんでした。

## 脅威モデル

role-setはローカルジェネレーターです。サーバーではありません。リッスンもせず、テレメトリーも収集しません。

実行は、指定されたプラン、ロールパック、および出力ディレクトリにアクセスします。`ingest`と`store`は、指定されたストアファイルにもアクセスします。`write`、`pilot-auto`、および`critic-control`は、それらが`--mock`でない場合に、ループバックエンドポイントにアクセスします。`--mock`は何も送信しません。ジェネレーターとそのスクリプトは、リポジトリ内のファイルを読み書きし、モデルは呼び出しません。

実行は、クラウドモデルサービス、ポッド、レンタルアカウント、またはレンタルAPIキーにはアクセスしません。シールされた行、保留されたセット、またはインタビューセッションも読みません。`ingest`は、指定されたコミットで、指定されたaspire-siクローンから12個の公開インタビューの質問を読み込み、それらを繰り返す行を拒否するだけです。それらは保存されません。`store status`は、行ではなく、カウントを返します。脆弱性を発見した場合は、[SECURITY.md](SECURITY.md)の連絡先に報告してください。

## テスト
