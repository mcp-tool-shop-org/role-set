**オープンな環境で開発されたプロトタイプ。** アドバイザリーおよび実験的：インターフェースとデータ構造は予告なく変更される。ロールセットが記述した内容は、誰かが確認するまでトレーニングデータにはならない。すべての項目は、R&Dによる主要なチェックと2回目の確認を経て、トレーニングセットに近づく。

ロールセットは、ロールを定義する項目を計画し、ライターが記述すべき部分を記述し、各項目が通過したゲートを記録する。また、コードでBタイプのパズルを構築し、モデルがそれを見る前に検証する。これはジェネレーターであり、審査官ではない。優れたロールホルダーとは、人々が記述するロールパックの中に存在するものである。

ライターと批評家は、明示的なポートを通じてのみ`http://127.0.0.1`にアクセスできる。それ以外は、1バイト送信する前に拒否される。ロールセットは、マシンをレンタルしたり、ポッドに触れたりすることはない。実行時にポッドを使用する場合、オフリグがレンタルし、ロールセットはループバックトンネルのみを確認する。

設計図は、[docs/role-set-design.md](docs/role-set-design.md)と[docs/generator-design.md](docs/generator-design.md)にあり、プログラムと整合性が保たれている。実行ノートは、[docs/runs/](docs/runs/)にある。

## インストール

Python 3.13+ (3.15)、uvによって管理。1つの実行時依存関係：[aspire-si-gates](https://github.com/mcp-tool-shop-org/aspire-si) 1.4.0、aspire-siコミット`388a6bc`に固定。ゲートはコピーではなくインポートされる。

```text
uv sync --frozen
```

## ロールパック

ロールパックとは、人々が1つのロールに対して記述したテキストである。ロールセットは、それをスライスして提供し、何も追加しない。そのハッシュは、すべての承認されたレシートに記載されている。

- **検証者**（`roles/verifier`）。`pack sync`は、特定のコミットにおけるローカルのaspire-siクローンから、レッスン、18の特性、種類テーブル、修正、およびルールをコピーする。`pack verify`は、コピーをマニフェストと比較する。新しいクローンには、ソースリスト、除外リスト、および`defects.jsonl`（レビューで発見された欠陥クラスのカタログ）のみが含まれる。残りは同期によって補完される。
- **擁護者**（`roles/advocate`）。このリポジトリに人々が記述したパックで、モデルのテキストは含まれていない。ディレクターは、2026年10月14日にパックを承認し（プルリクエスト#56のコミット`ffb9546`）、バッチ1がそこで構築されている。それは、#56がマージされるまで`main`には含まれない。バッチ1には、3つの特性が含まれている：`failed-gate-first`、`exact-figures`、および`faithful-relay`。擁護者の項目がパイロット読み取りに合格するまで、それはトレーニングデータではない。

## T10ジェネレーター

Bタイプのパズルは、以前は手書きで記述され、その後チェックされていた。現在では、コードがパズルを構築し、検証し、モデルはそれを言葉で表現するだけである。ジェネレーターは、`role_set.generate`パッケージである。厳密なサイズに関するレッスン（「正確に」、「少なくとも」、「最大で」）であるT10は、0.2.0で変更された部分である。T12レシピ（特定の日に有効だったバージョン）も構築される。T11は構築されない。

**構築によって検証される。** 構築者は、隠された解をサンプリングし、答えが確定するまで、その解で真である手がかりを追加し、答えが不要とするすべての手がかりを削除する。ソルバーはモデルをチェックする。次に、構築者はR&Dの4つのT10読み取りを実行する：「正確に」を「少なくとも」として読み、「正確に」を「最大で」として読み、「少なくとも」を「正確に」として読み、「最大で」を「正確に」として読み取る。パズルは、これらの読み取りのいずれかを単独の特性の手がかりに適用すると、答えが変化する場合にのみ保持される。他のカウントの手がかりで合格するパズルは、欠陥クラス`trait_not_tested`であり、拒否される。

**The cell map.** Each pack, question and seed maps to a structural cell: the entity count `n` (3 to 5), the count word `op`, `k` (1 to n−1), and `ifs`, the number of `if` clues (0 to 2). Set questions use all three count words. Claim questions use "exactly" only, because "at least" and "at most" cannot change a claim's verdict. The usable cells are probed once and committed in `t10_cells.json`.

**主張軸`if_shape`。** 主張セルは、その`if`の手がかりの形状も指定する。7つの形状がある：`none`は、`if`がない場合、`pos`または`neg`は、1つの`if`がある場合（その結果の極性による）、および`chain`、`shared_consequent`、`shared_antecedent`または`disjoint`は、2つがある場合。縮小されたパズルが形状を失う構築は、同じシード内で再試行する。

**アロケーター。** 1つの質問と1つの値カウントに対して、20個のシードのファイルは、構築を開始する前に、最小コストフローによって1回割り当てられる。各パックの20個のシードは、20個の異なるセルを使用する。`if`の手がかりがないセルは、ファイル内で最大2回使用される（ゼロ・イフ・キャップ）。他の訪問は、チューニングシードでより多くの異なるスケルトンを生成したセルを優先する。これらの重みは、2値パックと3値パックで別々に保持される。

**多様性の下限。** すべての層（セットと主張、2値と3値）：少なくとも75％の異なるカノニカルスケルトン、スケルトンは最大3回、1つのパックのファイル内でスケルトンが2回以上出現しない。下限は、ロックされたシードで判断される。ロックされたシード101〜120では、3値の主張は120個のうち118個の異なるものに達し、最大の繰り返しは2である。

**コミットされたレコード。** `t10_record.json`は、1,280個の構築（シード1〜20、61〜80、81〜100、および101〜120、すべてのパック、両方の質問）を保持し、それぞれにセル、`if_shape`、試行回数、およびカノニカルスケルトンが含まれる。ジェネレーターソース、セルテーブル、キャパシティテーブル、およびパックデータにわたるsha256を保持する。テストは、ロールセット自体のインポートの下で閉じられているファイルリストを保持する。通常のCIテストジョブは、数分でハッシュとレコードからの下限をチェックする。すべてのパズルの徹底的な再構築は、`sweep`ジョブとして、`workflow_dispatch`でのみ実行され、レコードからの違いがある場合は失敗する。

**キャパシティゲートとヘッドルーム。** `scripts/t10_usable_cells.py --check`は、各層の供給量、需要量、およびヘッドルームを報告し、ファイルが配置できない場合は数値で失敗する。`if_shape`を使用すると、3値パックは合計で61個の使用可能な主張セルを持つことになる（以前は27個）。どのパックもゼロ・`if`訪問を必要とせず、テストでは、12個の3値パック（実際の6個と6個のクローン）を、ファイル内で繰り返しなく配置する。

## コマンド

`role-set --help`は、コマンドを一覧表示する。以下の各行は、今日存在するコマンドである。フラグは、各コマンドの`--help`にある。

| コマンド | その機能 |
|---|---|
| `plan` | バッチ内のすべてのスロットを、シードから書き換える。モデルの呼び出しは行われない。同じシードは、同じプランを記述する。 |
| `cost` | 計画を開始する前に、ポッドの実行時間とコストを見積もります（`two-card`または`frontier`）。これはあくまで見積もりです。 |
| `pack sync` / `pack verify` | ローカルのaspire-siクローンから、特定のコミット時点の検証パックをコピーし、そのコピーをマニフェストと比較します。 |
| `harvest` | 固定されたリポジトリからライセンスチェック済みの抜粋をローカルプールにコピーします。クローンディレクトリは記録されません。 |
| `write` | ランナー。`--mock`は、モデルやコストなしで実行します。実際の実行には、ループバック`--endpoint`と`writers.json`からの`--model`が必要です。 |
| `readout` | 各レッスンと種類ごとに1回の実行を報告し、成功または失敗を、`batch-report.json`を含むディレクトリから行います。 |
| `critic-control` | レビューされた項目に基づいて、批判的な評価を行います。グラントとハートビートファイルが必要です。`--trait-leg`と`--answer-leg`がそれらの処理を実行します。 |
| `ingest` / `store` | レシートをストアに記録し、ファイアウォールを設置します。`store status`はカウントを報告します。`store void`は無効なものを追加します。 |
| `pilot-auto` | 有料ランチャー：ループバックの準備ができたら、書き込みを行い、中断された場合に再起動できます。 |
| `puzzle-check` | データファイルとその`.models.jsonl`サイドカーに対して、タイプBのソルバーを実行し、繰り返される事実の骨格を拒否します。 |

```text
uv run role-set plan --lessons T02,T03 --seed 0 --out plan.json
uv run role-set write --plan plan.json --pack roles/verifier --out out --mock
uv run role-set readout --run out/mock
uv run role-set puzzle-check tests/fixtures/puzzle-check/sample.jsonl
```

ジェネレーターは、まだ`role-set`コマンドを持っていません。その3つのスクリプトは、コミットされたテーブルとレコードを作成します。

| スクリプト | その機能 |
|---|---|
| `scripts/t10_usable_cells.py` | すべてのセルをプローブし、`t10_cells.json`を書き込みます。`--check`は、コミットされたテーブルに対してキャパシティゲートを実行し、プローブは行いません。 |
| `scripts/t10_cell_capacity.py` | チューニングシード1、21、および41の各セルについて、層ごとに異なる骨格の数をカウントし、`t10_capacity.json`に記録します。 |
| `scripts/t10_variety_record.py` | 記録されたすべてのパズルを`t10_record.json`に再構築します。`--check`は、コミットされたレコードを検証し、ロックされたシードの数値を表示します。 |

## ゲート

5つの種類：

- **A.** 指導のための文章。評価はありません。検証器が実行され、特性チェックは参考情報として扱われます。
- **B.** 有限の割り当てパズル。ソルバーがモデルをチェックします。批判者の回答は参考情報として扱われます。
- **C.** 意図的に欠陥が仕込まれたチェッカー、または正しかったチェッカー。評価と証拠のチェックは拒否されます。欠陥チェックは記録され、拒否は行われません。
- **D.** 2回のターン。評価と証拠のチェックは拒否されます。特性チェックは参考情報として扱われます。
- **E.** 書面によるクイズ、または評価クイズ。書面によるEには評価チェックはありません。評価タイプのEは、評価と証拠をチェックします。

評価と証拠のチェックは拒否されます。特性、回答、および欠陥のチェックは記録され、それらの制御がパスするまで拒否は行われません。特性の処理は、全体で85%のバーに対して40.3%であり、最悪の特性は70%に対して12.5%でした。回答の処理は、90%のバーに対して62.7%でした。2026-10-11の欠陥制御では、24件中9件が合格しました。

Bソルバーは、その閉じたルール形式のセットで、有限の割り当てパズルを処理します。最大6つのエンティティ、3つの属性、および20万件の割り当てです。思考をモデルと比較することはありません。自由テキストの素材に対する評価キー付きのB項目は、ソルバーの範囲外であり、`puzzle-check`はそれを範囲外としてカウントし、合格とはカウントしません。

ストアのファイアウォールは、取り込み時に保留、封印、およびインタビュー素材を拒否し、ステージ中にDEV素材を拒否します。その素材に対する読み取りパスはありません。ステアリングは設計されており、まだ実行されていません。

## 実行時に保持されるもの

すべての承認されたレシートには、プランハッシュとパックハッシュが含まれます。実行時にサンプルが使用された場合、サンプルコミットと除外ファイルハッシュも含まれます。使用された固定ルールがある場合、そのルールのハッシュも含まれます。生成されたパズルのレシートには、そのシード、試行、読み取り、難易度メトリック、および骨格、パック、およびソルバーのハッシュが含まれます。すべての書き込み呼び出しは、承認または拒否されたかどうかに関わらず、`drafts.jsonl`に保持されます。

## モデル

ライターピンはQwen3-235B-A22B-Instruct-2507、AWQビルド、Apache-2.0で、リビジョン`96548f657d772187f16e9f04bc50aec78a9f9cdd`で`qwen3-235b-instruct-2507`として提供されます。批判者のピンは`gemma4:31b`、ダイジェスト`6316f0629137b426c9d9b853ffc4c8209589f30ee39aebede6285096c0ff47e7`、Q4_K_M、Apache-2.0で、`http://127.0.0.1:11434`です。`writers.json`には、リハーサル専用のライターと、比較のための批判者もリストされています。ファイルにない名前は拒否され、`cloud`を含む名前も拒否されます。

ローカルGPUは、グラント内でのみ、批判者とリハーサルライターに使用されます。グラントは、`--grant`と60秒以内に変更されたハートビートファイルです。ハートビートファイルは開かれません。実行時にロードされた批判者は、エラーが発生した場合も含めて、終了時にアンロードされます。`--mock`は何もロードしません。

## パイロット

3つの有料パイロットは、[docs/runs/](docs/runs/)に記録されており、すべて2026-10-11に実行されました。それぞれ、$3.52、$3.61、$2.80です。これらは、このREADMEに記載されている唯一のコストの数値です。それらのいずれかの行も、トレーニングセットには含まれていません。パイロット2では、R&Dの49件の候補に対するキーチェックで、15件が記述されたとおりに合格し、機械的な修正後にもう15件が合格し、19件が不合格となりました。パイロット3は何も書き込みませんでした。

## 脅威モデル

role-setはローカルのジェネレーターです。サーバーではありません。リッスンせず、テレメトリも収集しません。

実行は、プラン、ロールパック、および指定された出力ディレクトリにアクセスします。`ingest`と`store`は、指定されたストアファイルにもアクセスします。`write`、`pilot-auto`、および`critic-control`は、それらが`--mock`でない場合に、ループバックエンドポイントにアクセスします。`--mock`は何も送信しません。ジェネレーターとそのスクリプトは、リポジトリ内のファイルを読み書きし、モデルは呼び出しません。

実行は、クラウドモデルサービス、ポッド、レンタルアカウント、またはレンタルAPIキーにアクセスしません。封印された行、保留されたセット、またはインタビューセッションを読み取りません。`ingest`は、指定されたaspire-siクローンから、指定されたコミット時点の12件の公開インタビューの質問を読み取り、それらを繰り返す行を拒否するだけです。それらは保存されません。`store status`は、行ではなく、カウントを返します。脆弱性を発見した場合は、[SECURITY.md](SECURITY.md)の連絡先に報告してください。

uv sync --frozen
